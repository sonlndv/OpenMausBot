### Reading the tables

- **Laptop / iPad / phone** mean available viewport, not device detection: reference widths 1366 / 820 / 390 CSS px. At 768 px the inline sidebar is eligible; below it, “sidebar” or “row” means open the labeled list first. iPad Split View may use the phone column. A repeated control name means the same component is reached by the workflow’s stated entry, not that it was exercised on all three devices. Side-panel fit is separate from the sidebar breakpoint: 920 / 1040 / 1280 / 1536 px gates depend on the panel combination.
- **Both** means Simple and Advanced. Host refers to the *serving workspace* unless Electron is named. A direct browser session has no `window.ogb`; it is not the Electron remote-client mode. Reader, writer, editor, and manager describe required capabilities, not new global roles. Pairing scopes, membership, personal/shared side, resource ownership, entitlement, feature switches, hardware and pending state still constrain each action.
- **Supported** means an eligible source entry was traced, **not an interactive pass**. **Missing** names the exact absent web entry or mode; another entry is recorded where traced. **Host-only** names the required bridge/service even on laptop web. **Unresolved** is a qualification gap: an entry or effect could not be certified from source for the named case. The outcome column gives the result to check, not a claim that it occurred. A mode switch, hover, raw HTTP request, guessed deep link, or native-only control is not a substitute for a missing touch action.
- Each row links to concrete callers and the closest existing fixture/recipe. Fixtures vary in scope: an API test can prove enforcement or persistence, not layout access; a desktop fixture does not prove web support. No tests or device passes are implied by a link. Named buttons describe intent; labels are localized.
